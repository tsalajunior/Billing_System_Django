GNU gettext / msguniq fix for Django on Windows
================================================

Problem:
- `python manage.py makemessages -l fr` fails with:
  `CommandError: Can't find msguniq. Make sure you have GNU gettext tools 0.19 or newer installed.`

Why this happens:
- Django needs the system command `msguniq` from GNU gettext.
- It is not a Python package issue; it is a Windows PATH / installation issue.

Step 1: Install GNU gettext on Windows
-------------------------------------
Option A — Official installer:
1. Open your browser.
2. Go to: https://mlocati.github.io/articles/gettext-iconv-windows.html
3. Download the latest gettext installer.
4. Install it.

Option B — Chocolatey:
1. Open PowerShell as Administrator.
2. Run:
   choco install gettext

Option C — winget (if available):
1. Try:
   winget install --id=GNU.Gettext.Gettext -e
2. If that fails, use the official installer above.

Step 2: Locate the msguniq.exe file
-----------------------------------
In PowerShell, run:

Get-ChildItem "C:\Program Files" -Recurse -Filter msguniq.exe -ErrorAction SilentlyContinue
Get-ChildItem "C:\Program Files (x86)" -Recurse -Filter msguniq.exe -ErrorAction SilentlyContinue

If you found it, note the folder. Common location:
C:\Program Files\gettext-iconv\bin

Step 3: Add the gettext bin folder to PATH
------------------------------------------
In PowerShell, run:

$env:Path += ";C:\Program Files\gettext-iconv\bin"

Then verify:

msguniq --version

You should see output like:
msguniq.exe (GNU gettext-tools) ...

Step 4: Activate the virtual environment
----------------------------------------
From the project root:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
& "D:\.dev\new\Billing_System_Django\venv\Scripts\Activate.ps1"

Then verify Django:

python -m pip show django

Step 5: Run makemessages again
------------------------------
From the project folder:

python manage.py makemessages -l fr

If you still get a locale error, fix Django settings first.

Step 6: Fix Django locale settings
----------------------------------
In `billing_system/settings.py`, use a list, not a set:

LOCALE_PATHS = [
    BASE_DIR / "locale",
]

Do not use:
LOCALE_PATHS = {BASE_DIR / "locale"}

Also ensure the locale folder exists:

mkdir .\billing_system\locale

Then run:

python manage.py makemessages -l fr

Step 7: Avoid scanning the virtual environment
---------------------------------------------
`makemessages` may scan `venv` and other files, which produces warnings/errors.
Use:

python manage.py makemessages -l fr --ignore=venv

Or, if needed:

python manage.py makemessages -l fr --ignore="venv" --ignore="requirements.txt"

Step 8: If requirements.txt is encoded badly
--------------------------------------------
This error can appear:
`UnicodeDecodeError: skipped file requirements.txt ... invalid start byte`

Convert `requirements.txt` to UTF-8 encoding, then retry.

Step 9: Permanent PATH setup for Windows
----------------------------------------
Run once in PowerShell:

$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if (-not $userPath.Contains("C:\Program Files\gettext-iconv\bin")) {
    [Environment]::SetEnvironmentVariable(
        "Path",
        "$userPath;C:\Program Files\gettext-iconv\bin",
        "User"
    )
}

Then close and reopen PowerShell.

Final check:
-------------
In a fresh PowerShell window:

msguniq --version
python manage.py makemessages -l fr

If both work, the issue is fixed.

Notes:
- The error is not caused by Django itself.
- It is caused by missing GNU gettext tools or PATH not including the bin folder.
- After installation, Django should work normally.
